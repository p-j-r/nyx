# Golden changes (ems)

Golden files are the numerical oracle (ADR 10). A change is listed here with the reason; none is made to hide a difference. These five files moved here from `femcore/tests/golden_frames` with the ems kernels (restructure phase 4, ADR 45); their numbers are unchanged by the move.

## 2026-11-04, `emw_pml_x.json` (phase 3, linear algebra; decided by paul: adopt the extra mode for now)

* **What changed**: the file had 3 modes, it has 4. The new 4th mode is `neff 4 = 1.730216 -5.076e-6i` (Q = Re/(2|Im|) = 1.704e5, quasi-TM (z), TE 0.000, Ey 0.188, P 1.000). Modes 1 to 3 are the same modes: `neff` 1.4393617 -2.791e-5i, 1.5762346 +7.334e-6i, 1.6630504 -5.812e-5i agree to 1e-12 relative in the real part (their tiny imaginary parts, 1e-5 to 1e-6, differ in the 7th digit, so Q 2 moves by 4e-7 relative); the fields of modes 1 to 3 differ by rounding only.
* **Why**: the study asks for 4 modes, and the old file holds 3. `nyx_ems::solve_mode_pairs_complex` (then `femcore::ems_pml`) drops a pair whose own error estimate is above its threshold, and its doc says so ("pairs the Krylov process could not converge are dropped"). The old solver therefore delivered only three acceptable pairs; I did not trace which of its limits (the 400-vector basis cap, the tolerance, the start block) left the fourth unconverged. The library's block Krylov-Schur (`solvers::driver::eigs_complex`, ADR 33) converges four pairs at the same tolerance (1e-10), and the fourth is the next eigenvalue of the list (0.067 in `neff` above mode 3), a genuine eigenvalue of the pencil. It is kept for now (paul's decision); whether the old file was an artefact of the old solver or the new solver adds a spurious pair has not been established independently (a check with a much tighter tolerance, or the mode field inside the PML, would settle it).
* **How to undo**: `NYX_OLD_LINALG` no longer exists (the old solver is deleted); restore the file from the commit before `Phase 3: adopt the extra converged mode` and lower the study's `n_modes` to 3.

## 2026-11-05, all five files (phase 5, `nyx-analysis`, ADR 56; asked for by paul: the polarization leaves the results)

* **What changed (scalars)**: the scalars `polarization N` are gone from every file; each file has the scalar `field frame` instead (`lateral x, normal z, propagation y, left-handed`, and `outside domains 2` for `emw_pml_x`). The polarization lines were **not** discarded: they are kept unchanged in `polarization.json`, and `tests/golden.rs` checks the analysis (`nyx_analysis::polarization`, a function of the result) against them: the class as text, the rounded numbers to 1.5e-3 (5e-3 for the two silicon-wire files, which are at the G2 tolerances).
* **Why**: results no longer carry an analysis (plan phase 5). The numbers of the analysis did not change, which is what the check against `polarization.json` shows.
* **What changed (sign of `Ey`)**: in `emw_pec_straight` (modes 1 to 3), `emw_soi_wire` (mode 1) and `emw_soi_hybrid` (mode 2) the probe values of the field `Ey` (the propagation component) have the opposite sign. Only the signs: `l1`, `max`, `n` and every other field are the same. **Why**: the real mode solver flips the transverse field so that its largest component is positive but did not flip `E_y` with it, so the relative sign of `E_y` between two modes was arbitrary; an analysis that reads the result (overlap of a degenerate pair) needs the consistent mode, and ADR 56 item 7 flips `E_y` with the rest. `emw_pec_tilted` and `emw_pml_x` (complex solver, one phase factor for all components) were consistent already.
* **How to undo**: restore the files from the commit before `Phase 5: nyx-analysis` and revert the `sg` factor on `E_y` in `nyx-ems/src/modes.rs` (`mode_fields_cells`); the analysis then differs only for degenerate groups.
