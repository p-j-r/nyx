# 124. One bar, five tabs, the viewport always on, the script as a dock, the physics as a dropdown

Date: 2026-11-24

## Status

Accepted by Paul on 2026-11-24 ("both, one after another", after reading `docs/ux/UX_RESET_PLAN.md`, sections 2, 3, 5 and 6), implemented on the bookmarks `ux-reset-5-script-dock` and `ux-reset-6-nav`. It amends ADR 88 and ADR 93 (the script editor was a sheet) and ADR 123 (which left navigation and Analysis for later). The shape comes from the sibling project `simgui` (one row of tabs, one viewport, a mode slider and a summary list), read from its screenshots, not run.

## Context

After ADR 123 the window still had four levels of navigation (workflow tabs; Concept, Build and Analysis; Geometry and Mesh preview; Boundaries, Study and Sweep), a rail of experiments that took 250 px, an inspector of 440 px, and a script sheet that covered the model. At 1500 px with the script open (as a dock, on top of the old layout) the viewport was 300 px wide. The Analysis page opened on a table that overran its panel and on a plot of `eigenvalue_im` against the run number; the field of the result, the modes and the summary were on another page, reached through a click on a run. Five filled accent controls were on screen at once (tab, section, sub-pill, physics pill, Compute). Choosing a physics changed `Project.active`, which is in the saved spec, so the autosave (`shell::flush`) compared another hash and stored a version and reread the workspace for a choice that changed no setting.

## Decision

* **The script is a dock on the right** (`sheets::script_dock`, drawn by `shell_ui` beside any page), resizable (340 to 900 px), toggled by Ctrl+Shift+R, the Script button of the bar and the File menu; its buttons are Run script, Check, Fill from model and a File menu (load, save, external `.py`); the editor takes the height, the check and the output sit under it. The model stays in view and what a script changes shows at once. The sheet remains only in the classic window (`--classic`, the tests of the plain window), which has no shell. A bottom dock was considered and rejected: it takes the height the viewport needs for a cross-section.
* **The physics of the project are one dropdown in the bar** (`wfview::physics_menu`): the ones in the project, then "Add ..." for the others (up to three), then "Remove ... from the project", the destructive entry last and apart. The pills and the remove button no longer sit in the inspector of the shell window; the text about what physics exchange is shown only when the project has more than one.
* **Which physics is on show is window state, not a change of the workflow.** `shell::spec_key` hashes the spec without `active`; `flush` and the draft test compare that key, so a switch writes no version and rereads nothing. A Compute still stores the exact spec (`shell_compute` clears the stored key before its flush), so a run is tied to a version that names the physics it solved; the store (`commit_spec`) decides whether that is a new version. The saved `active` is the one of the last real change or run. The file format is unchanged (ADR 63).
* **One bar, five tabs, the viewport always on.** `Part` (Concept, Build, Analysis) and the sub-pills are gone. The bar (`wf_bar`) holds the experiment menu and the physics dropdown on the left and, on the right, `Show: Geometry | Mesh | Result`, `Runs (N)` (from the second run on), Script and Compute, the one filled button. The left panel (`wf_inspector`, 320 to 640 px, resizable) is one row of text tabs (`kit::tabs`: the one on show in bold with a 2 px accent line) over the editor of the tab: Geometry, Materials, Physics, Study (the sweep is a section of it, closed by default) and Results. The viewport is the centre of every one of them. While a run of the workflow goes, the live run screen replaces the panels, as before.
* **Results is the page the person asked for.** The Results tab is `tab_results` (the result list, the mode slider with `<` and `>` and the label of the mode, the Field and Colours lists, the range, mesh edges, Fit view, the Summary list, the polarization when there is one, Export). Under the viewport, when the result has several solutions, `results_panel` plots them against the mode number; the status line under that gives the facts of the mesh and the name of the result. A new result opens the Results tab and the field (`push_result`). The "Field viewer" page and its "Back to runs" are gone.
* **A click on the mode plot chooses the mode.** The plot under the viewport (`results_panel`) takes a click: the solution nearest in x (`tabs::nearest_solution`) is shown, as with the slider and the arrows; the one on show is a larger gold point (a gold line for a time series), and the header says "click the plot to show one".
* **The runs are a page of their own** (`wf_runs`, `Sub::Runs`), not the first thing seen: the plot only when at least two runs differ in the plotted quantity (a flat line of identical runs says so in words instead), "Functions on these runs" behind a closed header, then the filter, the columns menu and the table, which fills the page and clips to it. Compare opens from it and returns to it. The engine commands and the data are as they were; only the default presentation changed.
* **Experiments are a menu of the bar** (`experiment_menu`: choose, new blank, fork, link), not a rail. Versions, Share, Pin, Done, Notes, Open folder, the tag input and Close are one `More` menu of the header; the save state is a dot with its words as a tooltip when the title leaves little room.
* **One accent.** The filled accent colour is Compute and the accent line of the tab and of the workflow tab; the `Show` choices and the experiment, physics and `More` menus use the plain selection. The second Compute button of the Study tab and the tab headings that repeated the tab name are not drawn in the shell window.
* **The workflow tabs never scroll.** `shell::top_bar` draws only whole tabs (`shell::fit_window`, `kit::tab_width`): titles shorten from 22 to 16 characters before a tab is dropped, a tab that still does not fit is left out (the first ones, so the active tab stays in view), the ▾ menu lists them all and its tooltip says how many are shown. The scroll area, and with it a first tab half out of view, are gone; `Shell.scroll_to_tab` is removed.
* **No font is shipped.** The EB Garamond italic of ADR 123 was no longer drawn in anything; `crates/app/assets/fonts/` (the file, `OFL-EBGaramond.txt`, its README) is deleted, `theme::title_family` and its empty family with it. The packager no longer copies a `fonts` folder or the OFL text (`nyx-install` `bundle.rs`, `nyx-pack.rs`; amends ADR 122), and NOTICE, README, the About sheet, the installer notice and the installer window stop naming the font. Inter and JetBrains Mono are still read when the user has them (`theme::first_font`); the fonts inside egui keep their own licences and stay listed.
* **Names.** The menu and palette actions are `ShowGeometry`, `ShowMaterials`, `ShowPhysics`, `ShowStudy`, `ShowSweep`, `ShowResults` (Alt+1 to Alt+6) and `ShowRuns`; the script command `section` takes `geometry|materials|physics|study|sweep|results|runs` and keeps `concept`, `build` and `analysis` (geometry, physics, results) for `tools/ux-shots.sh` and older scripts; `view field` opens the Results tab; `sheet script` opens the dock.

## Consequences

* At 1500 px the viewport is about 830 px wide with the script closed and 375 px with it open (300 px with the dock on the old layout, measured on the shots of 2026-11-24).
* No engine command, schema, contract exemplar or file format changed (ADR 19, 63): `docs/architecture/contracts/` and `VERSIONS.md` have no new line. Which physics a saved workflow opens with is the one of its last stored change or run.
* The tests that clicked "2 · Build", "3 · Analysis", "Your script..." and "Run .nys script", and read the inspector on the right of the window, use the new tabs and places (`app::tests::e2e_gui_*`); new tests: `shell::tests` (the spec key, a switch writes no version), `menu::tests` (the actions open the tabs and the runs page), `app::tests::a_new_result_opens_the_results_tab_with_the_field`.
* In a window narrower than about 960 px, or beside the script dock, what is shown (`Show`, `Runs`) goes to a row of its own under the bar, and the left panel scrolls (both axes) instead of widening: a tab with a wide row does not take the viewport.
* **Looked at on 2026-11-24 (light theme, 150 percent, 3D).** Light: the results, study, runs and script dock read well (the viewport canvas stays dark by its own setting). 150 percent (1300x800 shots, about 867x533 points): the strip of the modes under the viewport left too little height, so it is drawn only when the page has more than 380 pt of height (otherwise the slider and the Summary still choose the mode) and never takes more than 40 percent of it; below 700 pt of width (scale, or the script dock in a small window) the bar puts Show on a row of its own and Compute and Script on a third, where they overlapped the physics menu. 3D (block cantilever, rectangular cavity): fine; the "deformation scale" row overflowed the panel and its slider showed no rail, so the label has its own line and the rail is visible; the frequency axis of the eigenmode plot is in GHz, not `10000000000`. Not looked at: light theme at 150 percent, 200 percent, a 3D result with the dock open.
* Not decided here and so not changed: whether experiments, versions and the dashboard stay at all (they stay, as menus); the name "Workflows"; 200 percent scaling and the combinations listed in the previous bullet.
