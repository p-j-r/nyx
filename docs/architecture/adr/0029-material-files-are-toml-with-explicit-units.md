# 29. Materials are TOML files with explicit units and a checked stiffness

Date: 2026-11-04

## Status

Accepted (gate G4 answered by paul on 2026-11-03: TOML). Supersedes the in-code material data of ADR 1 (`sapphire()`, `silicon()`) once the engine loads the library (phase 7).

## Context

`material.rs` described four crystal classes by named constants and carried two materials written in code. The plan asks for materials that are easy to write by hand and complete when needed: the full elastic matrix in the reduced Voigt form, the other tensor properties checked, units always written.

## Decision

* One material is one TOML file (`materials/*.toml` is the shipped library, loaded at run time by `Library::load_dir`; the code holds no copy). `format = 1` is required. Unknown keys are errors with a "did you mean" suggestion. Errors name the material, the table and the key, in plain words.
* **Units are never assumed.** A quantity is `"496.8 GPa"`, `{ value = .., unit = ".." }`, or a bare number next to a declared unit (`unit` in `[elastic]`, `<key>_unit` elsewhere). Dimensionless entries (Poisson's ratio, relative permittivity) are bare. A unit of the wrong kind is refused with what was expected. Everything inside the library is SI.
* **Stiffness** (`[elastic]`) in exactly one of five ways, all giving the same 6x6 matrix `c` (Pa, textbook Voigt order 1=xx 2=yy 3=zz 4=yz 5=xz 6=xy, engineering shear, crystal frame): class and independent constants (isotropic, cubic, hexagonal, trigonal, tetragonal, orthotropic, monoclinic with unique axis y or z, triclinic); the matrix (full 6x6 or the upper triangle as rows of 6, 5, 4, 3, 2, 1); the compliance as constants or matrix (the matrix inverse of the stiffness in Voigt form, so the shear entries carry the usual factors, which the loader derives); isotropic pairs (E and nu, lambda and mu, K and G).
* **Checks**: symmetry of a full matrix, entry by entry; positive definiteness through the eigenvalues of the Mandel-normalised matrix, with the Born criteria in the message for a cubic crystal; consistency with a declared class (the first offending entry and the relation it breaks); derived entries written anyway (`c66` of a hexagonal crystal) must agree; Poisson's ratio range. Permittivity and thermal conductivity must be positive in every direction, electrical conductivity not negative, expansion only symmetric.
* **Other tensors** (permittivity, thermal and electrical conductivity, expansion): one value, three (x y z), six (xx yy zz yz xz xy), a 3x3 array, or `{ perp, par }` for a uniaxial crystal about crystal z.
* Orientation is not a property of the material: the project places the crystal with Bunge angles (`Elastic::global`, `MaterialSpec::anisotropy`), as before.
* `MaterialSpec::to_toml` writes a file back (class and constants if the file gave them, the matrix otherwise; comments are not kept; numbers round-trip to 1e-12). `.nyx` archives embed the TOML text of the materials they use (engine, phase 7).
* The legacy `Stiffness` enum gains `General(M6)` so that a general matrix reaches the existing kernels through `Anisotropy`; `sapphire()` and `silicon()` stay until the engine loads the library, and a test pins them to the library files.

## Consequences

* A schema (`material_schema.v1.json`, generated by `material::schema`) documents the format; the loader is the authority. The contract test checks that the schema lists exactly the keys the loader accepts.
* Importing the refractiveindex.info format is not implemented (default of this phase); `source` records where numbers come from.
* Piezoelectric tensors, temperature-dependent stiffness and viscosity are not in format 1.
