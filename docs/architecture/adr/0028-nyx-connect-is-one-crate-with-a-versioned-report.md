# 28. `nyx-connect` is the only copy of the Connect logic, and its outputs are versioned contracts

Date: 2026-11-04

## Status

Accepted by this change (phase 7a of the restructure plan: "merge `app/connect.rs` and `nyx-connect` into one"). Resolves ROUGH_SPOTS R07. Supersedes ADR 15 in part (the Connect menu keeping its own `.nyx-backup` logic in `app`).

## Context

`crates/app/src/connect.rs` (two clients, one `.nyx-backup` kept for good) and `crates/nyx-connect` (five hosts, a handshake test, a command line, a time-stamped backup per change) did the same job in two ways. They disagreed on the backup rule, the entry written (the app added `env: {}`), how a moved server is found, and the statuses. The `ai/` split that kept the app from calling the crate ended with ADR 26.

## Decision

* One crate, `nyx-connect`, library and binary. `app` depends on it and has no Connect code of its own; `nyx-mcp` may use it too. It stays a leaf of the layering table (`serde_json` only).
* Modules: `env` (where the machine keeps things; tests build an `Env` by hand), `hosts` (the table of five hosts and the entry each wants), `config` (status, connect, disconnect), `server` (finding `nyx-mcp`, the handshake probe), `report` (the JSON reports and their schema).
* **Rules for a host's config file** (tested in `tests/behaviour.rs`): only the `nyx` entry is touched; other keys and servers keep their order (`serde_json/preserve_order` is therefore a requirement of this crate, set in its own manifest); a file that is not plain JSON is never written; keys the user added to the `nyx` entry (an `env`) survive a reconnect; the file is replaced through a temporary file and a rename.
* **Backup**: the first time nyx changes a file the original is copied to `<name>.nyx-backup`; that copy is never overwritten, so it is the file as it was before nyx. (The crate's earlier `<name>.nyx-backup-<unix seconds>` could be overwritten by a second change in the same second and piled up; the app's rule won.)
* **Entry**: Claude Code gets `{type: stdio, command, args: [], env: {}}` (what `claude mcp add` writes and what the app wrote), VS Code `{type, command, args}` under `servers`, the others `{command, args}` under `mcpServers`.
* **Finding the server**: `NYX_MCP` (if set and wrong, nothing is found), then the folder of the running program; the menu then offers "Locate nyx-mcp...". That is the whole lookup of a shipped program. Only when the program sits in a cargo build tree (`is_cargo_build_tree`: its folder holds cargo's `deps` and `.fingerprint`, so `--release` developer builds count and an install never does) is the search widened to five folders in total, the program's own folder and its four parents, and for each of them its `target/release`. This was decided with paul on 2026-11-04 because a packaged install should not go looking in unrelated parent folders. The old compile-time guess from `CARGO_MANIFEST_DIR` is dropped (it pointed at a target folder that the shared target directory of ADR 26 no longer is).
* **Report**: `nyx-connect list|connect|disconnect|test --json` prints `{"schema": "nyx-connect.<list|change|test>", "version": 1, ...}`. The JSON Schema is generated by `report::schema()` and checked in.

## Contracts

* `connect_hosts` v1 (`contracts/connect_hosts.v1.json`): per operating system, each host's config file relative to the home folder, servers key, hint and the entry written. AI hosts that registered nyx earlier read these entries; changing one is a version bump (ADR 19).
* `connect_report` v1 (`connect_report.v1.json` examples, `connect_report.v1.schema.json`). The test validates the examples and the live output of the built program against the schema with a small validator that refuses keywords it does not know. A new optional key keeps v1; a renamed, removed or re-typed key is v2.

## Consequences

* The Connect menu now lists every installed host (not only Claude Code and Desktop) and shows "no supported AI app found" when there is none.
* Tests that look at key order of a config file are on purpose here: the order is the behaviour, and the crate enables `preserve_order` itself, so ADR 26's rule (no key order in data-format tests) does not apply to them.
* A later engine command can call `nyx_connect::list` and return the `list` report as is.
