# Interface contracts

The rule is ADR 19. Each contract is an exemplar file here plus a test that generates the same bytes from the code.

| Contract | Pins | Test | Run |
|---|---|---|---|
| `problem_spec` | serde shape of `ProblemSpec` (one spec per physics), XML encoding, leniency, `Physics` order | `crates/femcore/tests/contracts.rs` `problem_spec_*`, `physics_enum_*` | `cargo test --release -p femcore --test contracts` |
| `solve_result` | structure of the old (window) `SolveResult`, order refusal, `"cancelled"`; since phase 4 through the bridge `nyx_engine::legacy` | `crates/nyx-engine/tests/legacy_contract.rs` | `cargo test --release -p nyx-engine --test legacy_contract` |
| `frames` | wafer-frame constants, name tables, tensor permutations, PML axes | same file, `frames_*` | same |
| `mesh` | label bases (1 for domains and boundaries), node order per cell type, no curved-node storage, `.fmsh` version and round trip, PML numbering; exemplar `mesh_cells.v1.json` | same file, `mesh_*` | same |
| `kernel_stages` | public stage functions of every kernel family (R26 closed in phase 3); since phase 4 they are those of the physics crates | `crates/nyx-dfs/tests/contracts.rs` (dfs); `crates/nyx-sms/tests/contracts.rs` (sms); `crates/nyx-ems/tests/contracts.rs` (ems); composition in `tests/stages.rs` of each crate | same |
| `geom_model` | geom depends on serde only; golden feature lists round-trip key for key | `crates/geom/tests/contracts.rs`; `tests/goldens.rs` | `cargo test --release -p geom --test contracts` |
| `script_api` | what a script can rely on: extension, the `nyx` object and its call forms, default limits, path-guarded arguments, clock and random policy, the script kept with a run, the worker program; exemplar `script_api.v1.json` (the commands are `engine_commands`) | `crates/nyx-script/tests/contract.rs` | `cargo test --release -p nyx-script --test contract` |
| `store` | `workflow.json`, `runs.jsonl` line, format gate, metric names, concept card | `crates/nyx-store/tests/contracts.rs` | `cargo test --release -p nyx-store --test contracts` (`-- --include-ignored` shows R25) |
| `mcp_tools` | tool names, annotations, arguments, handshake, handle format | `crates/nyx-mcp/tests/contracts.rs` | `cargo test --release -p nyx-mcp --test contracts` |
| `problem_spec` v2 | serde shape of the problem envelope (`nyx-physics`), one spec per physics | `crates/nyx-physics/tests/contracts.rs` `problem_spec_v2_*` | `cargo test --release -p nyx-physics --test contracts` |
| `solve_result` v2 | serde shape of a result | same, `solve_result_v2_*` | same |
| `physics_descriptors`, `physics_api` | descriptor types; trait surface, registry rules, error codes | same | same |
| `physics_dfs_result` | the shape of a dfs result per study (names, units, components, per-cell fields, scalar names; no numbers) | `crates/nyx-dfs/tests/contracts.rs` `result_shape_exemplar_is_stable` | `cargo test --release -p nyx-dfs --test contracts` |
| `physics_ems_result` | the shape of an ems result per kind of kernel (names, units, per-cell fields, scalar names; no numbers) | `crates/nyx-ems/tests/contracts.rs` `result_shape_exemplar_is_stable` | `cargo test --release -p nyx-ems --test contracts` |
| `physics_sms_result` | the shape of an sms result per study and kernel variant (names, units, components, per-cell fields, scalar names; no numbers) | `crates/nyx-sms/tests/contracts.rs` `result_shape_exemplar_is_stable` | `cargo test --release -p nyx-sms --test contracts` |
| `physics_dfs`, `physics_sms`, `physics_ems` | the descriptors each physics declares (studies, conditions, properties, fields, couplings, generated JSON Schema) | `crates/nyx-{dfs,sms,ems}/tests/contracts.rs` | `cargo test --release -p nyx-dfs -p nyx-sms -p nyx-ems --test contracts` |
| `engine_commands`, `geom_operations`, `engine_project` | the command catalog with schemas, the geometry operation descriptors, an example project (provisional layout) | `crates/nyx-engine/tests/{contracts,geomdesc}.rs` | `cargo test --release -p nyx-engine --test contracts --test geomdesc` |
| `material_schema`, `material_example` | the JSON Schema of material file format 1 (schema version 1.1); two files that use every section and model and the `MaterialSpec` they resolve to; the schema lists exactly the loader's keys | `crates/femcore/tests/material_contract.rs` | `cargo test --release -p femcore --test material_contract` |
| `connect_hosts`, `connect_report` | the config entry written into each AI host's file; the JSON and JSON Schema of `nyx-connect --json` | `crates/nyx-connect/tests/contracts.rs` | `cargo test --release -p nyx-connect --test contracts` |
| `layering` (tests only) | which workspace crate may depend on which | `crates/nyx-engine/tests/layering.rs` | `cargo test --release -p nyx-engine --test layering` |
| `linalg_options`, driver | `EigenOptions` shape and defaults; the driver surface the kernels call; closed-form direct solve, Laplacian and non-symmetric eigenvalues, dense helpers, cancel | `crates/femcore/tests/linalg_contract.rs` | `cargo test --release -p femcore --test linalg_contract` |
| `mesh_request`, `mesh_report`, `adapt_maxwell` | the serialisable mesh job (request, report, JSON Schemas); the residual estimator trait and its parts; 3D adaptive and structured meshes keep the label map and the physical numbering (ADR 50 to 55) | `crates/femcore/tests/contracts.rs` `mesh_request_*`, `adapt_maxwell_*`, `mesh_geom3d_*` | `cargo test --release -p femcore --test contracts` |

Rewriting an exemplar: `NYX_WRITE_CONTRACT=1 cargo test ... --test contracts <test name>`. Do it only with a `VERSIONS.md` entry. None of these tests depends on frozen floating-point values, so they pass on a machine where the golden files fail (R22).

Files: `problem_spec.v1.json` (old `ProblemSpec`, until phase 4), `problem_spec.v2.json`, `solve_result.v2.json`, `physics_descriptors.v1.json`, `physics_{dfs,sms,ems}.v1.json`, `physics_{dfs,sms,ems}_result.v1.json`, `mesh_request.v1.json`, `mesh_report.v1.json`, `mesh_request.schema.v1.json`, `mesh_report.schema.v1.json`, `store_workflow.v1.json`, `store_run.v1.json`, `mcp_tools.v1.json`, `engine_commands.v1.json`, `geom_operations.v1.json`, `engine_project.v1.json`, `connect_hosts.v1.json`, `connect_report.v1.json`, `connect_report.v1.schema.json`; versions in `VERSIONS.md`. Exemplars are compared as values, never as text: the order of the keys of a JSON object is not part of a contract (ADR 26).
