### U1, tokens and accessibility (bookmark `ux-u1-tokens`)

* **`tokens.rs`** (new, pure data, no egui types): every role of `docs/ux/tokens.json` in light and dark, and the two region palettes. Tests: contrast of 22 text, accent, status and edge pairs per look (text 7, others 4.5, control edge 3); the region palettes **reproduce the validator's numbers** (dark all-pairs: colour-blind 6.7, normal 15.8; light: 8.8 and 18.4; the Machado 2009 simulation and the OKLab distance are ported from `validate_palette.py`) and must stay above the validator floors (colour-blind 6, normal 15, lightness band, chroma 0.10); neutrals keep chroma <= 0.026 (measured values round to it, test uses 0.0265); **the constants equal `tokens.json`** (a test parses the JSON), so the document and the code cannot drift.
* **`theme.rs`**: both looks are built from the tokens and installed with `set_visuals_of`, spacing and text styles on both with `all_styles_mut`, and the theme preference is pinned (`apply_mode(ctx, dark)`; following the system is U2, so a dark-mode host does not change the window yet). Control edges are `control_edge` (>= 3:1), dividers `separator`, focus = the 2 px accent stroke of `widgets.active` (egui draws focus with the active visuals). The old fixed constants (`AMBER`, `PLUM`, `INK`, `GREEN`, `RED`, ...) are gone: every call site uses a role function (`accent`, `on_accent`, `success`, `danger`, `activity`, `activity_text`, `raised`, `edge`, `scrim`, ...).
* **`kit.rs`**: `primary` and `pill` use `on_accent` (ink on the dark pink); `danger` uses the danger role; `chip` and the bar track use tokens (the track is outlined); `dot` is replaced by `State` (Done, Running, Waiting, Failed, Idle) with a **drawn glyph** each (check, disc, ring, cross, hollow ring: no font needed) and `status(ui, State, label)`; new `tab()` (28 px, glyph, 24 x 24 close target, selected = tint + 2 px accent bar, focus ring, `WidgetInfo` for screen readers) used by the Dashboard and the workflow tabs in `shell.rs`.
* **`tests/colour_literals.rs`**: a **ratchet**, not the strict rule of the plan. `kit.rs`, `shell.rs` and `sheets.rs` have no colour literal left, but about 64 remain in `app.rs`, `tabs.rs`, `viewport.rs`, `dashboard.rs`, `wfview.rs`, `geomui.rs` and `scene.rs`; they are counted per file and may only go down (a file not in the table may have none). Most are data and canvas colours that U4 replaces, and the status colours of `app.rs`/`tabs.rs` (Stale, connected, converged) that U3/U5 take over. Deviation from the plan, on purpose.

### U2, conventions (bookmark `ux-u2-conventions`)

Settings keeps Follow system / Light / Dark. Before this step "system" was saved but ignored at start (the window opened light).
* **Settings added** (new fields of `nyx_store::Settings`, all with serde defaults so old `workspace.json` files load): **Contrast** (follow system / standard / high: `control_edge_high` role at 4.5:1 and 1.5 px strokes; "follow system" reads the Windows flag with one `SystemParametersInfoW(SPI_GETHIGHCONTRAST)` call declared by hand, no new dependency), **Reduce motion** (animation time 0, still progress block), **Canvas** and **Colour regions by** (stored, **shown disabled** until the data colours of U4 exist: a light canvas would leave the viewport overlays unreadable), zoom. `app.rs` takes the viewport background from `theme::canvas` (setting, default dark = the old colour).
