* **Sweep section** (`sweepui.rs`, new): a third pill "Sweep" in the Build inspector. Pick a numeric **geometry parameter** of the model, a range and a number of points; the section shows the **engine's dry run** ("5 points: 5 meshes, 5 solves", from `Engine::check_list` on the `sweep_run` command, the same count `nyx check` prints; its problems are shown in the engine's words); "Run sweep" submits `sweep_run` (the points are queue jobs at priority 3, so a Compute asked for meanwhile goes first), a table of the points (glyph and word, value in SI, stage or time) fills in while the busy chip and the queue popover show them, "Cancel the sweep" is `sweep_cancel`, and a chart of one metric against the parameter appears as points finish (default metric as on the Analysis page). The page is not locked during a sweep: the points solve frozen copies, and a test checks the window's own project is unchanged.
* **Every finished point is recorded as a run** of the experiment (the engine of the window has no workspace link, so `apply_point` recorded nothing for it): the window writes the run with the point's own spec (the parameter set) and the **metrics the engine now puts on each sweep row** (`"metrics"`, additive: the same keys a Compute's run carries, so one table and one plot hold both; `nyx-engine/src/sweep.rs`, asserted in `tests/sweep.rs`). A draft workflow gets its folder when the sweep starts. A failed point is a failed run; a point cancelled before it started leaves none.
* **Limits:** only a geometry parameter can be swept from the window (a study value or a material is a sweep an assistant or a command list can ask for); a parameter that is an expression over others is not offered; the value column assumes lengths in metres ("450 nm"), true for the examples, wrong for a dimensionless parameter; one sweep at a time; a sweep belongs to the workflow it was started in (its runs go there even if another tab is open); closing the window ends the sweep (the points are jobs of this process).
* **Analysis plot (B5):** marker **shape per version** of the set-up (a legend names them when there are two or more), the **last run labelled** at the end of the line, **ticked runs ringed** in the text colour. The default metric is now the first that **varies** (it was the first in alphabetical order, so the example showed a flat imaginary part of zero): neff, then the eigenvalue, then the first varying one, never the run time. Shapes were not shot with two versions (no script command edits a set-up); rings and the end label were.
